## 三、模型与第三方依赖

- 本项目**不训练任何模型**；
- 大模型为可选能力：通过 OpenAI 兼容端点接入百炼、Ollama、vLLM 等服务，`LLM_API_KEY` 仅通过环境变量注入；
- `DEMO_MODE=offline`（默认）使用本地确定性通道，不向任何外部模型服务发送数据；
- `DEMO_MODE=live` 时，提示词与检索证据会发送至你配置的模型服务商，请自行评估其数据使用条款与合规资质；
- 第三方开源组件的名称、用途与 License 清单见 [04-技术实现说明.md](04-技术实现说明.md) §四；
- 可选 profile（MinIO / Ollama / Prometheus / Grafana）以独立服务方式运行，分别遵循其自身许可；如用于生产，请再次核对版本与许可条款。

## 四、安全与隐私

### 4.1 密钥与配置

- 仓库不包含任何真实密钥；`.env`、`.env.*` 已纳入 `.gitignore`；
- 生产部署必须通过环境变量或密钥管理服务注入 `SECRET_KEY`、数据库口令、模型 API Key 等敏感配置；
- 若发现密钥曾意外提交，请立即轮换并在 Git 历史中清理（本仓库当前已做全历史扫描）。

### 4.2 平台内置安全机制

- 认证：JWT（OAuth2PasswordBearer）+ argon2 密码哈希 + 登录限流；
- 授权：RBAC 角色权限矩阵；工具调用经统一权限网关；
- 数据访问：检索权限过滤下推到存储层，无权限数据不出库；
- 脱敏：按角色的动态脱敏规则表，界面 / API / 日志三处口径一致；
- 审计：Hook 决策与工具调用只追加记录，支持按 `trace_id` 复原；
- 记忆合规：个人记忆查阅 / 更正 / 删除 / 导出（PIPL 最小集），仅本人可访问并全程留痕；
- 输出治理：引用存在性校验、合规强制提示、低置信标注、先校验后外发。

### 4.3 生产部署检查清单

- [ ] 修改全部种子账号口令（`SEED_*_PASSWORD`）并启用强口令策略；
- [ ] 设置独立 `SECRET_KEY`，关闭调试模式；
- [ ] 配置 CORS 白名单，禁止 `*` 与 credentials 组合；
- [ ] 启用 HTTPS 与安全响应头；
- [ ] 使用托管数据库与密钥管理服务，限制网络暴露面；
- [ ] 配置备份、日志留存、监控告警与审计查阅权限；
- [ ] 对真实业务数据完成分类分级、脱敏与访问审批。

### 4.4 安全漏洞报告

请勿在公开 Issue 中披露可直接利用的漏洞细节。请通过仓库维护者在 GitHub 主页公开的联系方式私下报告，并附上复现步骤与影响范围；维护者确认后会尽快修复并在合适时机公开说明。
