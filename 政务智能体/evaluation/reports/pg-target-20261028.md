# PostgreSQL 目标库验证（2026-10-28）

> 实例：阿里云 RDS PostgreSQL 18.6，公网地址，仅用于本次验证。
> 验证库：`gov_validation_20261028`（本次新建）。实例上另有 3 个非模板业务/测试库，未连接、未修改。
> 结论：PG 迁移、pgvector、政务版本边界检索和知识混合检索可用；性能为远程小数据实测，不是生产容量结论。

## 一、环境与迁移

| 项目 | 结果 |
|---|---|
| 数据库版本 | PostgreSQL 18.6 |
| 扩展 | pgvector 0.8.1.3（本次在验证库创建） |
| Alembic | `upgrade head` 成功，16 个迁移全部执行 |
| 表数量 | 54 张（public schema） |
| 向量/全文结构 | `kb_chunk.embedding VECTOR`、`kb_chunk.content_tsv TSVECTOR`、HNSW + GIN 索引 |
| 政务条款向量 | `gov_policy_clause.embedding` 为 JSONB，1024 维；94 条条款均已写入 |
| 初始化脚本 | 修复多次 `asyncio.run` 导致模型客户端跨事件循环复用的问题；SQLite 双跑和 PG 重跑均 exit 0 |

## 二、政务接口验证

公开政策双版本已初始化：492 原版 38 条、711 修订版 56 条，均审核发布，嵌入模型 `text-embedding-v3`。

| 请求 | 结果 | 时延 |
|---|---|---|
| 2019-05-14 检索答复期限 | 200，2 条，全部 492 原版 | 1232.2 ms（冷启动） |
| 2019-05-14 解读 | 200，answer，2 条 claim，492 原版 | 382.1 ms |
| 2019-05-15 检索答复期限 | 200，6 条，全部 711 修订版 | 284.7 ms |
| 2019-05-15 解读 | 200，answer，6 条 claim，711 修订版 | 489.2 ms |

版本边界行为正确：2019-05-15 生效日当天切到 711 修订版，前一天仍为 492 原版。

## 三、知识混合检索验证

向验证库导入 8 条外部知识（mock）后：

- `kb_chunk` 8 条，`content_tsv` 和 `embedding` 均非空，向量 1024 维；
- `无氟防水` 检索返回 12 条证据，冷启动约 978 ms，后续约 144–219 ms；
- `plainto_tsquery('simple', '无氟 防水')` 对 token 化文档匹配为 true；
- 未 token 化的原始中文 `to_tsvector` 不切词，直接匹配为 false，符合“应用侧 jieba 预分词写入 content_tsv”的设计。
- `EXPLAIN (ANALYZE, BUFFERS)`：Planning 0.634 ms，Execution 0.170 ms；8 行数据走 `ix_kb_chunk_domain_id` 索引后排序，未使用 HNSW（小表和混合评分下正常），不能据此判断大规模性能。

## 四、发现与限制

1. **政务条款向量使用 JSONB + Python 余弦**，不是 pgvector/HNSW；政策库变大后，政务检索的向量部分会走 Python 计算，可能成为扩展瓶颈。知识域 `kb_chunk` 才使用 pgvector/HNSW。
2. 远程 RDS 首请求约 1.2 秒，热请求约 0.3–0.5 秒；数据量很小，不能当生产容量或并发结论。
3. 本次只验证单进程、小数据、无并发；未做连接池耗尽、长事务、故障切换和备份恢复。
4. 私有化/信创/目标政务云仍未验证；本报告只证明公有 RDS PostgreSQL 路径可用。
5. 验证库保留供复核；未触碰实例上其他业务/测试库。

## 五、结论

- PG 迁移、pgvector 扩展、政务版本边界检索、知识全文/向量混合检索：**PASS（小数据、单进程）**。
- 生产目标环境、私有化、信创、并发与容量：**未验证**。
- 后续如继续优化，应优先评估把 `gov_policy_clause.embedding` 迁移为 pgvector + HNSW，或在政策库规模上做独立压测。
