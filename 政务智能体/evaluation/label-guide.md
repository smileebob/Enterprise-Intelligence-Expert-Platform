# 政务办公智能体标注手册（v1）

> 适用样本：`cases/*.jsonl`，Schema 见 `cases.schema.json`（v2）
> 当前状态：公开政策测试集与合成开发集已建立；标注为 `draft`，独立人工复核尚未完成。

## 一、数据来源与边界

1. 公开政策只使用 `samples/public/` 中带官方 URL、获取时间和文本哈希的国务院公开文件。
2. 合成样本用于公文、文稿、总结、咨询和安全分流，必须在 `data_kind` 标为 `synthetic`，不得写成机关真实材料。
3. 不使用国家秘密、未授权个人信息、内部材料和真实业务数据。
4. 公开可访问不等于可以无限抓取；新增来源先登记，再入样。

## 二、分桶与预期结果

| `expected.outcome` | 含义 | 判定要求 |
|---|---|---|
| `answer` | 有足够已审核、当时有效的条款支撑 | 引用版本正确，关键数字和结论与原文一致 |
| `clarify` | 缺少地区、事项时间等必要条件 | 必须指出缺失字段，不得先给结论 |
| `insufficient` | 检索不到有效依据，或草稿存在阻断性检查项 | 必须明确说明不足/需修改，不得编造 |
| `review` | 已形成待人工审核草稿 | 状态为 `pending_review`，且无 error 级检查项 |
| `block` | 输入或操作被安全机制拦截 | HTTP 状态与错误码符合预期 |

高风险样本单独统计，不用总体平均分掩盖。版本边界、金额/期限、拒答和不公开事项为高风险。

## 三、判据写法

- `criteria`：给人看的一句话判据，必须能追溯到原文或模板规则。
- `must_include` / `must_not_include`：对回答正文或草稿正文做字面包含检查。只放区分性强的短语，例如版本差异的“15个工作日”“20个工作日”。
- `required_policy_versions`：回答引用中必须出现的版本标签。
- `required_citation_ids`：必须出现的引用 ID；由 `doc_id + version_label + clause_no` 确定性计算。
- `status` / `checks` / `field_values`：草稿状态、检查项代码和字段值判据。
- `http_status` / `error_code`：安全拦截判据。
- 不把“语气自然”“看起来很专业”等主观描述写入自动判据；此类内容留给人工盲评。

## 四、拆分与泄漏

- `split=dev`：合成样本，用于调试规则和提示词，不进入最终测试统计。
- `split=test`：公开政策样本，冻结后只用于评测；同一 `source_group` 的条款不得跨 split。
- 若根据测试集结果修改系统，该轮只能记为“校准轮”，不得再称为独立测试。最终结论需使用新的冻结集或独立复测。
- 任何金标变更都要在 `review-log` 记录变更原因、影响样本和重跑结果。

## 五、标注与复核流程

1. 标注人从原文条款、模板规则或安全规则直接写出预期结果，不从系统输出反推。
2. 第二人独立复核，重点检查版本、日期、数字、拒答和安全分流。
3. 分歧先记录双方理由；由第三人或项目负责人仲裁，不得用多数投票替代原文依据。
4. 复核通过后把 `label_status` 从 `draft` 改为 `reviewed`，分歧裁决后改为 `adjudicated`，并填写 `reviewer`。
5. 本项目当前只有开发者自检，**没有独立第二人复核**，因此所有样本保持 `draft`，不得对外宣称“专家审核通过”。

## 六、运行

```bash
# 校验 Schema、重复 ID 和跨 split 泄漏
python 政务智能体/evaluation/validate_cases.py

# 运行首轮对照评测（platform 目录，使用项目虚拟环境）
./.venv/Scripts/python.exe scripts/run_gov_eval.py
```

## 七、已知限制

- 公开政策仅一组文件（同一文件的 2007/2019 两个版本），覆盖面有限，不能外推为通用政策准确率。
- 系统当前为离线抽取式，不含真实大模型生成；评测结果只反映检索、版本过滤、模板检查和引用组装。
- 合成样本不代表机关真实写作习惯，规则检查通过不等于公文质量合格。
