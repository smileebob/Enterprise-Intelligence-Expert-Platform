# 企业级领域专家 Agent 平台（AngentPlatform）

[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](https://www.gnu.org/licenses/gpl-3.0)

> **传化 × 动势「AI 重构产业·架构师大赛」参赛作品**
> 参赛团队：**智涌**
> 参赛赛道：**Track 01 · AI＋功能化学（主赛道）** ｜ **Track 03 · AI＋生物技术（副领域验证）**

一个「**多模态知识底座 + 自成长领域智能体 + 权限化工具网关 + 企业级记忆**」的通用平台：把散落的内外部专业知识沉淀为**可追溯、可评估、可成长**的知识资产，让每个业务领域都能快速装配出「懂行、可信、越用越聪明」的专家智能体。平台采用「**通用底座 + 可插拔领域插件**」结构，本仓库交付两个领域实例——**AI 化学家**（主领域，端到端可信 Demo）与 **AI 产业招商专家**（副领域，配置装配，验证平台通用性）。

## 一、业务场景

### 1.1 主赛道：Track 01 AI＋功能化学 ——「AI 化学家」

传化功能化学深耕纺织印染助剂领域，客户在面料类型、加工工艺、生产设备及目标性能上差异巨大，业务呈现**需求高度个性化、产品品类复杂、专业服务依赖专家经验**的特点。技术工程师需要综合查阅产品资料、历史试样报告、工艺文件及外部文献，依靠个人经验完成产品选型与方案设计。

官方点名的五大痛点，即本作品的攻坚目标：

1. 客户需求描述不专业、不完整，难以转化为标准化技术需求；
2. 专业知识分散于非结构化文档，跨文档查询与关联困难；
3. **内外部知识融合不足——外部通用知识容易覆盖企业内部专有知识**（核心痛点）；
4. 现有 AI 工具停留在检索拼接，缺乏跨文档分析与深度推理；
5. 方案生成依赖专家经验，历史经验难以组织化复用。

官方"同样关注"的三个创新方向（配方优化 / 设备清洗切换优化 / 缺料预警），平台已预留扩展点并给出逐方向实现路径与验证方案（复用打分器插件点、@tool 工具网关、Celery 周期任务等已落地机制）。

> 细部场景说明（官方赛题还原、痛点逐条映射、演示路径、**三创新方向实现路径**）：**[doc/01-化学赛道场景说明.md](doc/01-化学赛道场景说明.md)**

### 1.2 副赛道：Track 03 AI＋生物技术 ——「AI 产业招商专家」

传化科技城面向创新药、基因与细胞治疗、AI 制药、医疗器械及医美等前沿领域招商，面临**前沿企业发现难、产业资源匹配效率低、企业市场拓展能力不足**的挑战。官方推荐场景要求：整合工商/融资/专利/科研/产业动态识别高潜企业 → 生成企业画像识别入驻需求 → 智能匹配园区空间/政策/产业资源。

本作品以**轻量领域插件**装配该场景，用于证明平台的横向扩展能力——同一底座换套配置即装配新领域。官方三个创新方向（智能选址落地 / 政策精准匹配 / 销量增长）同样已预留扩展点并给出实现路径（插件的 `match_park_resources`、`verify_qualification` 工具与「落地需求/政策需求」澄清槽位即为现成挂点）。

> 细部场景说明（含能力映射、**三创新方向实现路径**、数据边界与终赛路径）：**[doc/02-生物赛道场景说明.md](doc/02-生物赛道场景说明.md)**

## 二、核心方案

### 2.1 一句话方案

「**通用底座 + 可插拔领域插件**」：以知识管道 **KP-1（六级信息分级 + 分区召回 + 融合冲突消解 + 可追溯引用）** 为差异化核心，配套六维评估、五类安全 Hook、四层记忆与自成长闭环，构成企业级领域专家 Agent 平台；化学为主领域做深做透，生物招商为副领域验证通用性。

### 2.2 五大设计主线

1. **多模态知识底座 + 六级信息分级**：知识按可信度分六层（原始材料/内部专有/外部通用/当事方陈述/AI 推断/人工确认），融合优先级全序 `confirmed ≥ internal > stated > external > ai_inferred`——**内部实测永远优先于外部普遍结论**，冲突双方保留并显式标注；合规场景（CS-05）反转为由确定性规则表执行的「法规优先」。直击"外部覆盖内部"核心痛点。
2. **六维评估 + 领域标准层**：规则引擎打基线分 + 大模型校准（**±10 限幅 / 偏差 >15 转人工 / 失败降级规则分**），评分可解释、可追溯、版本化演进；招商领域零改代码复用同一引擎。
3. **自成长闭环**：专家反馈（采纳/修正/否决）→ 正负样本 → 案例库/纠错规则 → 标准草稿审核发布，平台越用越聪明。
4. **四层记忆**：会话级/用户级/企业级/领域级，含个人 → 企业晋升机制（≥2 人同向 + 管理员确认）与 PIPL 查阅/更正/删除/导出。
5. **五类安全 Hook 治理**：输入/检索/工具调用/输出/记忆写入全链路审核、按角色动态脱敏（界面/API/日志三处口径一致）、trace_id 全程可审计复原。

### 2.3 架构总览

```
platform-web（Vue 3 独立工程：对话台/评估卡/装配台/审计台）
        │ REST /api/v1 + SSE（先校验后外发）
app/ FastAPI（create_app 工厂 + APIRouter 业务域）
core/ 通用底座：abstraction │ knowledge(KP-1) │ orchestration
      memory │ evaluation │ gateway │ guardrails │ growth │ admin
domains/ 领域插件：chemical（主，完整五要素）+ investment（副，轻量）
adapters/：storage_pgvector / storage_sqlite / model_gateway / ...
PostgreSQL 16 + pgvector │ Valkey │ Celery
```

## 四、技术实现

> 摘要版；完整版见 **[doc/04-技术实现说明.md](doc/04-技术实现说明.md)**。

- **关键算法与模型**：KP-1 知识管道（六级分级 + 0.6 向量/0.4 全文混合检索 + 优先级全序融合 + 冲突检测）；六维评分公式（D1–D6）+ 大模型校准协议；自研状态图编排引擎（interrupt/resume + 检查点 + 重规划 ≤2）；离线确定性模型通道（SHA256 哈希嵌入 + 规则组装，零云依赖可复跑）。**不训练任何模型**，预留模型注册表与插件点。
- **技术架构**：FastAPI 0.115（应用工厂 + APIRouter 业务域）+ SQLAlchemy 2.0 + PostgreSQL16/pgvector + Valkey + Celery；前端 Vue 3.5 + Vite + TS strict + Element Plus；Docker Compose 五容器一键起栈（可选 observability/ollama/minio profile）。
- **数据来源**：全部为赛事模拟数据（`is_mock` 标注），含 5 个内置冲突场景（CS-01~05）；终赛真实数据对接路径已明确（解析适配器扩展 + 标准层校准）。
- **外部依赖**：全部为开源组件（MIT/BSD/Apache-2.0 等，License 清单见 doc/04 §四）；大模型为可选 OpenAI 兼容端点（百炼等），密钥仅环境变量注入，无密钥时 `DEMO_MODE=offline` 完整演示。

## 五、运行方式

### 5.1 Docker Compose 一键起栈（推荐）

```bash
cp platform/.env.example platform/.env   # 可填 LLM_API_KEY；留空则默认 DEMO_MODE=offline 离线演示
docker compose up -d --build
docker compose run --rm api python scripts/init_demo.py   # 建表→种子→导入模拟数据→装配双领域→冒烟
# http://localhost:8080 （web） ｜ http://localhost:8000/docs （API）
```

### 5.2 本地零云依赖（无 Docker 亦可）

```bash
cd platform
python -m venv .venv && ./.venv/Scripts/activate   # Windows；Linux 为 .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                                # 默认 DEMO_MODE=offline 确定性运行
python scripts/init_demo.py                         # 初始化 + 冒烟（SQLite + 内存缓存 + Celery eager）
uvicorn main:app --port 8000
# 前端另开终端：
cd ../platform-web && npm install && npm run dev    # http://localhost:5173
```

### 5.3 演示账号（种子数据，仅演示用途）

| 账号 | 口令 | 角色 |
|---|---|---|
| `expert` | `Expert@12345` | 领域专家用户（化学工程师） |
| `kbadmin` | `Kb@12345` | 知识管理员 |
| `admin` | `Admin@12345` | 平台管理员 |
| `auditor` | `Audit@12345` | 安全审计员 |

### 5.4 5 分钟演示脚本（评委路径）

1. 登录 `expert` → 对话台选「AI 化学家」→ 提问「客户要涤纶面料做无氟防水，要求耐洗 50 次不明显下降，无氟能做到吗？」→ 观察**思考步骤**与**逐条引用角标**（CS-01 冲突双方保留）。
2. 提问「客户做出口欧盟的户外面料，能用 C6 有机氟 TF-WR-6612 吗？」→ 观察**合规强制提示**（CS-05 法规优先）与**无氟替代推荐**、评估事件 **D6 ≤ 30 反转**。
3. 提问「帮我做防水整理」→ 观察**澄清追问** → 补充「涤纶面料，防水耐洗 50 次」→ 获得完整方案。
4. 右侧评估卡查看**六维得分/权重/依据/护栏** → 点「采纳」→ 知识管理员审核正样本、专家个人记忆出现偏好。
5. `admin` 登录 → 装配台「AI 产业招商专家」上线 → 切换领域提问「帮我找 AI 制药赛道的高潜企业」→ 企业六维画像 + 园区匹配。
6. `auditor` 登录 → 审计台按 trace_id 复原任一回合全链路 Hook 记录。
7. 量化对照：`python scripts/run_regression.py` → 8 问引用命中率、CS-01~05、反朴素 RAG 对照报告。

## 七、当前限制

1. 初赛全部使用**模拟数据**（已显式标注），未经真实数据量级检验；终赛对接路径已明确；
2. 招商副领域未接入实时外部数据源（工商/专利/投融资），实体消歧为已知后续难点；
3. 多模态当前覆盖文档/表格/结构化 JSON，图片与仪器图谱为后续里程碑；
4. live 模式回答质量取决于所接大模型；离线模式为确定性兜底；
5. 单机 Compose 为演示形态，生产化扩展思路见技术方案 06/08 篇；
6. 配方性能预测未训练专用模型，已预留插件点。
